= Analyzing Documents With Custom User-Defined Schemas

Analyze any type of document and fully customize the output structure by creating a Generic document action and enabling *Customize Schema*. Define the output fields and tables and configure prompt instructions for Einstein to analyze the document and extract the data.

include::partial$document-action.adoc[tag=definition] 

Enabling *Customize Schema* reduces the number of requests because IDP queries the entire document in one prompt, rather than making one request per prompt to Einstein as in a Generic document action without *Customize Schema* enabled. 

You cannot enable *Customize Schema* for existing document actions, you must create a new Generic document action.

== Create a Generic Document Action and Enable Customize Schema

To analyze documents and fully customize the output structure, create a document action of the Generic type and enable *Customize Schema*:

. In the sidebar, click *Document Actions*.
. Click *Create New*.
. Select the *Generic* type. 
. Enable *Customize Schema*. 
+
By enabling *Customize Schema* you can define fields and tables to create a structured output for your analyzed documents. This feature also enables an enhanced preview of the fields and tables in the document action builder.
+
If *Customize Schema* is disabled, you can still configure Einstein prompts to analyze the document. See xref:enhancing-data-extraction-with-einstein.adoc[] for instructions.
+
[WARNING]
When you create a document action without enabling *Customize Schema*, requests are not optimized and every prompt counts as one API call to the LLM.

. Provide a Name and click *Create*.

Next, use AI to discover the data to extract from the document or manually add the fields and tables to extract. 

[[discover-with-ai]]
== Discover Data to Extract from Your Documents with AI

You can use AI to automatically analyze the selected file and create the output.

. In the document action builder, click *Select Files* and select the files to use as an example or model for the extraction. 
. In the *Outputs* panel, select *Discover with AI* and click *Next*.
. (Optional) Provide instructions in natural language to specify what information to extract.
. Click *Discover*.
. Click *Save*.

== Manually Add the Fields to Extract

To configure the fields to extract and define the structure of the output document:

. In the document action builder, click *Select Files* and select the files to use as an example or model for the extraction. 
+
Skip this step if the example file is already loaded. 
. In the *Outputs* panel, click *Create Manually*. 
. Select the *Fields* tab. 
. Click *Start from Scratch* to add the first field. 
. Provide a name for the field and a prompt.
+
If you don't configure a prompt, Einstein scans the document and automatically extracts the data that better suits the field. However, make sure you test the output to confirm the extracted field matches the expected result. Otherwise, configure a prompt to provide Einstein with specific instructions about how to populate that field. 
. Click *Add New* to continue adding fields.
. Click *Run* and verify the results of the extraction. 
. Click *Save*.

== Manually Add the Tables to Extract

To configure data extraction from tables:

. In the document action builder, click *Select Files* and select the files to use as an example or model for the extraction.
+
Skip this step if the example file is already loaded. 
. In the *Outputs* panel, click *Create Manually*. 
. Select the *Fields* tab. 
. Click *Start from Scratch* to add the first table. 
. Provide a name for the table and a prompt if necessary to configure the data to extract.
. Click *Add New Column* and provide a name and prompt for the column. 
** Continue adding columns until the table is complete. 
. If there are more tables to configure, click *Add New* and repeat the steps to add the table columns.
. Click *Run* and verify the results of the extraction. 
. Click *Save*.

After you finish configuring the output schema for your documents, add reviewers and publish your document action.

[NOTE]
Some models provide self-reported confidence scores, which become less reliable as the document action gets more complex. See xref:supported-models.adoc#confidence-scores[Confidence Scores by Model] for additional information.

[[compare-models]]
== Compare Models Before Extracting Data

Compare the extraction results of different models on the same document before you decide which model to use. You can compare the results for fields and tables side by side with a baseline and up to two alternatives.

Compare models is available for Generic document actions with *Customize Schema* enabled.

=== Set Up and Run a Comparison

. In the document action builder, click *Select Files* and upload one or more files.
+
*Compare Models* is enabled after you upload at least one file.
. Click *Compare Models*.
+
The compare models setup page opens with the document that was in focus in the document action builder.
. Review the *Baseline* and *Alternative* models to compare.
. (Optional) You can add a second alternative and select another model for it.
. Click *Compare*.
+
The page shows the progress of the comparison, including any failures, and the model settings used. 
** To view the settings used for the comparison, click *View Model Settings*.
** To edit the comparison parameters, click *Edit Comparison* and then click *Compare* again.
. When the results are available, click *View Results* to review them in the *Fields* and *Tables* views.

=== Compare Fields

In the *Fields* view, compare the baseline against either alternative, or view the baseline and both alternatives next to each other by using the *Compare with* selector.

To show only the values that differ between models, select *Value differences only*. IDP highlights the differing values. If the results are identical, nothing is highlighted.

To show the confidence score of each returned value from every model, select *Show confidence*.

=== Compare Tables

Select the *Tables* view and compare values by customizing these options:

* *Table*: select the table to compare. You can select one table at a time.
* *Compare with*: compare the baseline against all models or against a single alternative at a time.
* *Match rows by*: defines how IDP matches each baseline row with a row in an alternative:
** *Exact rows* (default): IDP compares all the values in a baseline row with the rows in the alternative and matches only rows with identical values. If any value in a row differs, IDP can treat it as a different row and show it as a new row.
** A specific column: IDP matches rows using the value of the column you select. Use this option when a value can differ between models but both values can be correct.
* *Value differences only*: select this option to show only the values that differ between models.
* *Show confidence*: select this option to show the confidence score of each returned value from every model.

[[office-files]]
== Microsoft Office File Types Support

Generic document actions with *Customize Schema* enabled can analyze Excel (.xlsx) files. You upload, configure, and run these files the same way as any other file type. For supported formats, see xref:quotas-and-limits.adoc[].

IDP doesn't read the workbook directly. Before extraction, IDP converts the workbook to an A4 landscape PDF using its own pagination, and the model analyzes that PDF. As a result:

* A table that spans multiple sheets or print areas can split across pages.
* A large or dense sheet can cause the model to omit or alter data. If the results are incomplete, split the workbook into smaller files.

IDP doesn't support .xls files, .xlsm files, or password-protected workbooks.
